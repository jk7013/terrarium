# 🧑‍💻 Terrarium 개발용 Cursor 사용 가이드

> 목표:  
> Cursor가 “대필기”가 아니라 **짝궁 시니어 개발자**처럼 도와주게 만드는 사용 규칙 정리.

---

## 1. 기본 원칙

1. **설계와 책임은 내가 가진다.**
   - 엔드포인트, 함수 이름, 파라미터, 리턴 타입, 모듈 구조는 **내가 먼저 정한다**.
2. **Cursor는 “구현 보조 + 리팩터링 도우미”로만 쓴다.**
   - 한 번에 큰 파일 전체를 맡기지 않는다.
   - **한 함수 / 한 파일 / 한 단위 작업**만 요청한다.
3. **완전히 이해한 코드만 자동완성으로 수용한다.**
   - 탭 한 번 = “이 코드의 의미를 설명할 수 있다”일 때만 누른다.
4. **주석 → 코드 순서로 작업한다.**
   - 먼저 한글로 주석(알고리즘/단계)을 쓰고
   - 그 다음에 Cursor에게 “이 주석에 맞춰 구현해 달라”고 요청한다.

---

## 2. 개발 모드 두 가지

### 2.1 학습/연구 모드 (Terrarium 기본 모드)

- 목적: 구조 이해 + 파이썬 실력 향상 + 실전용 코드
- 규칙:
  1. **함수 시그니처, 클래스, Pydantic 모델 정의는 내가 직접 타이핑**
  2. 구현이 막힌 부분만 Cursor에 맡긴다.
  3. 한 번에 20~30줄 이상 제안 나오면 그대로 모두 수용하지 않고,  
     필요한 블록만 골라서 수용한다.
  4. Cursor가 만든 코드는 반드시 한 번 **줄 단위로 읽고, 모르는 부분은 질문**한다.

### 2.2 생산/야근 모드 (급할 때만)

- 목적: 속도 우선
- 규칙:
  - 반복 작업, 단순 래핑, 문서 정리 등은 뭉텅이 자동완성을 허용.
  - Terrarium 핵심 로직(RAG, 로깅, API 스펙 등)은 가능하면 이 모드에서 작업하지 않는다.

---

## 3. 작업 루틴

### 3.1 함수/파일 하나 작업할 때 공통 루틴

1. **설계 먼저**
   - 어떤 역할을 하는 함수/파일인지 한 줄로 정의
   - 입력/출력(파라미터, 리턴 타입) 정리
2. **시그니처 + 주석은 내가 쓴다**

   ```python
   def run_rag(request: QueryRequest) -> QueryResponse:
       """
       Terrarium 핵심 RAG 파이프라인 엔트리포인트.
       1. trace_id 생성
       2. trace 객체 초기화
       3. 모드(ephemeral/corpus)에 따라 분기
       4. retriever 호출
       5. reranker로 재정렬
       6. contexts 선택
       7. LLM 호출
       8. trace 로깅 + Response 생성
       """
       # TODO: 구현
   ```

3. **Cursor에게 구현 위임**

   - “이 시그니처와 주석을 기준으로, 함수 바디만 구현해 줘. 각 단계에 주석을 유지해 줘.”  
     같은 식으로 요청.

4. **코드 읽기 & 이해 체크**
   - 자동완성/제안 코드 그대로 수용하지 말고,
   - 줄 단위로 읽으면서 “이 줄이 무엇을 하는지” 설명할 수 있는지 확인.
   - 이해 안 되는 줄은 ChatGPT(시니어 동료 모드)나 Cursor에게 의미 설명을 요청.

5. **테스트/실행으로 검증**
   - 최소한:
     - `/health`, `/query`에 실제로 요청 보내 보기
     - 로그/trace 파일이 기대한 구조로 찍히는지 확인

## 4. Cursor에게 쓸 프롬프트 템플릿

> 아래 템플릿은 Chat 패널에서 사용할 용도.  
> “한 번에 한 작업만” 시키는 용도로 사용한다.

### 4.1 함수 구현 템플릿

```text
[역할]
너는 내가 이미 잡아놓은 설계와 시그니처를 기반으로, 
함수 "구현부만" 채워주는 보조 개발자다.

[요청]
아래에 내가 미리 작성한 함수 시그니처와 주석이 있다.
1. 시그니처/주석은 바꾸지 말고, 함수 바디만 구현해 줘.
2. 각 단계마다 주석을 유지하거나 보완해 줘.
3. 외부 의존 함수/모듈을 새로 만들 필요가 있다면, 
   "어떤 이름/역할의 함수가 필요할지"만 코멘트로 제안하고 실제 구현까지는 하지 마.

[코드]
(여기에 내가 작성한 함수 시그니처 + 주석 붙여넣기)
```

### 4.2 리팩터링/정리 템플릿

```text
[역할]
너는 내가 이미 작성한 코드를 더 읽기 쉽게 리팩터링하는 시니어 개발자다.

[요청]
아래 코드에 대해:
1. 동작은 변경하지 말고, 가독성과 구조만 개선해 줘.
2. 의미 없는 변수명/마법 숫자가 있으면 이름을 개선하되, 
   변경된 부분은 주석으로 짧게 이유를 적어줘.
3. 너무 복잡한 if/for 블록이 있으면 작은 함수로 분리해 제안해 줘.
4. 최종 코드 블록 아래에, "무엇을 어떻게 바꿨는지" 5줄 이내로 요약해 줘.

[코드]
(여기에 리팩터링할 코드 붙여넣기)
```

### 4.3 테스트 코드 생성 템플릿

```text
[역할]
너는 내가 작성한 함수에 대한 테스트 코드를 만들어 주는 보조 개발자다.

[요청]
1. 아래 함수/메서드에 대해 pytest 스타일의 테스트 코드를 작성해 줘.
2. "정상 케이스 1~2개 + 엣지 케이스 1개" 정도만 포함해 줘.
3. 테스트 함수 이름은 test_로 시작하게 해 줘.
4. 외부 리소스(DB/네트워크) 없이, 순수 함수 형태로 테스트 가능하게 만들어 줘.
5. 내가 이해할 수 있도록, 각 테스트 함수에 주석으로 '무엇을 검증하는지' 한 줄씩 적어줘.

[코드]
(여기에 대상 함수 코드 붙여넣기)
```

## 5. 자동완성(탭) 사용 기준

1. **“읽어서 이해한 후에만 탭으로 수용”**
   - 제안이 나오면 바로 탭 누르지 않고,  
     한 번 읽어보고 “이 줄이 뭘 하는지 설명 가능하다” 싶을 때만 수용.
2. **멀티라인 제안은 부분 수용**
   - 너무 긴 블록이 나오면,  
     필요한 부분만 마우스로 선택해서 수용하는 습관 들이기.
3. **핵심 로직은 Chat 패널에서 명시적으로 요청**
   - RAG 파이프라인, 로깅/트레이스 구조, DB 스키마 등  
     중요한 부분은 “자동완성”이 아닌 **명시적인 프롬프트 기반으로 작업**한다.

## 6. Terrarium 전용 공부 루틴 (Cursor와 함께)

Terrarium 개발할 때는 아래 루틴을 기본으로 가져간다.

1. **10분 – 시그니처/주석 작성**
   - 오늘 구현할 함수/파일의 역할을 정리하고
   - 시그니처 + 주석을 직접 타이핑한다.
2. **15분 – Cursor 도움으로 구현**
   - 위 템플릿을 사용해서 구현부만 요청.
   - 나온 코드 줄 단위로 읽고, 이해 안 되는 부분 표시.
3. **5분 – 이해 정리**
   - 이해 안 되는 부분은 ChatGPT에게 질문해서 개념/문법 정리.
4. **5분 – 메모**
   - 새로 알게 된 포인트를 `CONCEPTS.md` 등에 1~3줄로 정리.

이렇게 하면:
- Cursor를 IDE로 쓰면서도
- Terrarium 코드가 “실전에서도 쓸 수 있는 수준”으로 유지되고
- 동시에 파이썬/백엔드 기본기도 계속 쌓인다.
