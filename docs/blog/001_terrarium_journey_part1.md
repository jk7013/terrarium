# Terrarium 개발 이야기 1편
## "아무것도 안 되던 화면"에서 "질문하면 답하는 챗봇"까지

안녕하세요.  
이 글은 개발을 잘 모르는 분도 이해할 수 있도록, Terrarium 프로젝트에서 최근에 무엇을 했는지 이야기처럼 정리한 기록입니다.

---

## Terrarium이 뭐예요?

Terrarium은 쉽게 말해 **문서를 읽고 질문에 답해주는 백엔드 엔진**입니다.  
사용자는 채팅 화면에서 질문하고, 서버는 그 질문을 받아 AI 모델(Ollama + Qwen)에게 전달해 답변을 돌려줍니다.

조금 더 쉽게 비유하면:

- 채팅 화면 = 손님이 주문하는 창구
- Terrarium 서버 = 주문을 정리하는 직원
- Ollama/Qwen = 실제로 답변을 만드는 전문가

---

## 시작할 때 어떤 문제가 있었나요?

처음에는 Docker로 서버를 띄웠는데도 메인 화면이 열리지 않았습니다.

### 문제 1) 메인 페이지가 404 에러

- 증상: 브라우저에서 `/static/index.html` 접속 시 "파일 없음(404)"
- 원인: Docker 컨테이너 안에 `static` 폴더가 복사되지 않았음
- 해결: Dockerfile에 `static` 폴더를 복사하도록 수정

결과적으로, 이제 채팅 화면이 정상적으로 열리게 되었습니다.

---

## 화면은 열렸는데, 왜 답변이 안 왔나요?

다음으로는 "Ollama 서버에 연결할 수 없다"는 문제가 있었습니다.

### 문제 2) 컨테이너 안의 localhost 혼동

이 부분이 비개발자에게 가장 헷갈릴 수 있습니다.

- 컴퓨터(호스트)에서 Ollama는 잘 실행 중
- 그런데 Docker 컨테이너 안에서 `localhost`는 "내 컴퓨터"가 아니라 "컨테이너 자기 자신"을 뜻함

그래서 컨테이너가 Ollama를 찾지 못했던 것입니다.

### 해결 아이디어

- Docker 환경에서 호스트를 가리키는 주소(`host.docker.internal`)를 사용
- 실행 가이드도 함께 정리해서 재현 가능하게 문서화

---

## 그 다음엔 실제로 무엇이 동작하게 되었나요?

핵심은 "질문 분기"입니다.

### 1) 일반 질문은 AI로 전달

사용자가 일반 질문을 하면, Terrarium이 프롬프트를 만들어 Qwen에 전달하고 응답을 받습니다.

### 2) 날씨 질문은 weather tool 먼저 사용

사용자 질문이 날씨 관련이라고 판단되면:

1. weather tool이 외부 날씨 정보를 가져옴
2. 그 정보를 AI에게 "근거 컨텍스트"로 전달
3. AI가 그 정보를 바탕으로 친절한 문장으로 답변

즉, "AI가 무작정 상상해서 답하는 것"이 아니라,  
**툴이 가져온 실제 정보를 기반으로 대답하는 구조**가 만들어졌습니다.

---

## 지금까지의 성과를 한 줄로 정리하면?

**"화면도 안 뜨던 단계"에서 "질문하면 실제로 답하고, 날씨 질문은 툴까지 쓰는 단계"까지 왔습니다.**

---

## 아직 남은 큰 과제는?

다음 핵심 단계는 **벡터 색인 DB 연결**입니다.

이게 왜 중요하냐면:

- 지금은 주로 즉석 컨텍스트(ephemeral) 중심
- 앞으로는 문서를 미리 잘게 나눠 저장하고
- 질문이 오면 관련 문서를 빠르게 찾아서
- 더 정확한 답변을 만들 수 있게 됩니다

현재 계획은 FAISS 기반의 로컬 벡터 검색 방향입니다.
